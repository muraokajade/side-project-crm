# JobHunt UI/UX 方針

JobHunt の画面をどう作るかの判断基準。
「何を作るか(サービス仕様)」はこの文書の対象外で、決めるのは利用者本人。
ここに書くのは「決まったものをどう見せ、どう操作させるか」だけ。

最終更新: 2026-09-21

---

## 最優先

**転職・副業活動を素早く前へ進められること。**

迷ったらこの一点に戻る。画面の美しさ・情報の網羅性・実装の面白さは、
これを助けるときにだけ価値がある。

---

## UI原則

- **高密度** — 一覧性を優先し、巨大カードを避ける
- **高速** — 主要操作までのクリック数を少なくする
- **静か** — 過剰な色・装飾・アニメーションを避ける
- **明確** — 次に何を押すか迷わせない
- **一覧優先** — 詳細情報は詳細画面へ逃がす
- **モバイルでも自然に操作できる**
- **20〜100件になっても破綻しない**

---

## デザイン

- モダンな個人向け Web アプリ
- 情報密度は高いが窮屈にしない
- タイポグラフィと余白で階層を作る(罫線や色数を増やして作らない)
- CTA は数を絞って明確にする
- 同じ操作を複数箇所へ無意味に置かない

---

## 避けること

- 巨大カード
- ダッシュボード化
- 過剰な集計表示
- 大量のアイコン
- 派手なグラデーション
- 装飾目的の UI
- **UI 改善の名目で新機能を追加すること**

---

## 役割分担

| 範囲 | 決める人 |
|---|---|
| サービス仕様・何を作るか | 利用者(村岡) |
| UI/UX の具体的な表現 | AI に任せてよい |
| 最終判断 | 実際に JobHunt を使って決める |

機能を足したくなったら、それは UI の問題ではなく仕様の問題。
まず運用して、必要性が出てから仕様として判断する。

---

## 現在の実装での適用例

この方針を具体化した結果として、トップ画面は次の形になっている。
今後の変更もこの形を壊さない範囲で行う。

- **一覧** — PC では1案件=1行。案件名 → ステータス → 会社名 → 報酬 → 締切 → 詳細の順。
  概要は1行 truncate。`md` 未満では縦積みに折り返す。
- **詳細** — 媒体・カテゴリ・URL 全文・職種・勤務地・雇用形態・メモ等は
  一覧に出さず、「詳細を開く」でのみ表示する。
- **集計** — カードをやめ、`総数 n｜対応中 n｜終了 n｜お気に入り n` の1行に収める。
- **CTA** — `求人URLを登録`(主) と `手入力`(副) の2つだけ。
  一覧の直前のツールバーに置き、ヘッダーには登録操作を置かない。
- **ヘッダー** — サービス名と、アカウント/ゴミ箱/ログアウトのみ。
- **色** — ステータスと締切の切迫度の識別にだけ使う。装飾には使わない。

## 未対応として認識していること

実装しないと決めたのではなく、**運用してから判断する**もの。

- 並び替え
- ステータスでの絞り込み
- ページネーション / 仮想化

件数が 20〜100 件規模になったときに本当に必要か確かめてから、
サービス仕様として判断する。
